# Этап 2 — Капча при вступлении

## Реализованный контур

```text
Новый участник supergroup
  → Telegram chat_member update
  → капча включена? (глобальный профиль или индивидуальный)
  → restrictChatMember (mute) + ephemeral-сообщение с кнопкой «Я не бот»
  → callback_query от того же telegram_user_id
  → снятие ограничения, аудит CAPTCHA_PASSED
```

Само сообщение с кнопкой отправляется как ephemeral (Bot API 10.2, `receiver_user_id`) —
видимое только новому участнику, не всему чату. Остальные участники его вообще не видят
и не могут нажать кнопку. После успешной проверки сообщение удаляется отдельным методом
`deleteEphemeralMessage` (обычный `deleteMessage` для ephemeral-сообщений не работает —
их `message_id` всегда равен 0, реальный идентификатор лежит в `ephemeral_message_id`), а
подтверждение («✅ Проверка пройдена, добро пожаловать!») по-прежнему показывается
всплывающим окном через `answerCallbackQuery`. Сам текст сообщения (без плейсхолдеров —
статичный, показывается только адресату) редактируется через панель, в настройках капчи.

## Настройка

Раздел «Модерация» — глобальная политика по умолчанию для чатов с наследованием.
Страница чата (`/chats/[id]`) — только включение/выключение капчи для конкретного чата,
либо переключение на глобальный профиль — по той же схеме, что уже используется для правил
автомодерации. **Правило фиксированное, не настраивается**: новый участник мутится сразу при
вступлении и остаётся в mute, пока не нажмёт «Я не бот» — сколько бы времени это ни заняло.
Кто не подтвердит, будет исключён (не заблокирован — может зайти по новой ссылке и пройти
капчу заново) при следующей ежедневной проверке. Раньше был настраиваемый таймаут (1–1440
мин) и выбор «исключить/заблокировать» — убрали намеренно: таймаут всё равно проверялся раз в
сутки (см. ниже), так что точная цифра в минутах ничего не меняла по факту, только создавала
иллюзию точности.

## Честные ограничения этапа

- Работает только для supergroup (Telegram API не позволяет `restrictChatMember` в обычных группах).
- Проверка на совпадение `telegram_user_id` в `callback_query` остаётся как защита на всякий случай, хотя
  с переходом на ephemeral-сообщения (см. выше) кнопку физически видит только сам приглашённый участник —
  раньше, пока сообщение было публичным, это было единственной защитой от нажатия чужой кнопки.
- Исключение непрошедших капчу проверяется той же ежедневной cron-задачей
  (`/api/cron/moderation-expirations`), что уже снимает истёкшие временные mute — это единственный
  «дедлайн», который реально есть. Значит, между вступлением и исключением может пройти от нескольких
  минут до почти суток, в зависимости от того, когда именно человек зашёл относительно времени запуска
  задачи. Настоящий real-time контроль потребует более частого cron-триггера (доступно на платных
  планах Vercel) — сознательно не стали делать это предпосылкой запуска функции.
- Бот не имитирует прохождение капчи и не создаёт fake-события: запись в журнале появляется только при
  реальном нажатии кнопки или реальном срабатывании ежедневной проверки.
