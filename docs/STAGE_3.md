# Этап 3 — Апелляции и самостоятельная разблокировка

## Команды бота в ЛС

- `/start`, `/help` — приветствие и список команд.
- `/status` — сводка одним сообщением: пользователь, user id, текущий статус,
  осталось самостоятельных разблокировок, данные последнего mute (причина/чат/админ/дата).
- `/unmute` — самостоятельно снять mute без участия администратора, до 3 раз **в каждом
  чате отдельно** (не суммарно). Если mute сразу в нескольких чатах — бот просит указать
  номер чата (`/unmute 2`). После исчерпания лимита mute снимается только через `/appeal`.
- `/appeal` — апелляция на ban/warning с рассмотрением администратором (ниже).

## Реализованный контур апелляции (ban/warning)

```text
WARNING / MUTE / BAN выдан (вручную или automod)
  → бот пишет пользователю в ЛС с инструкцией
  → пользователь отвечает Reply "/appeal <причина>" на это сообщение
  → запись Appeal (PENDING) привязана к конкретному ModerationAction
  → админ открывает «Апелляции» → «Одобрить» / «Отклонить» (+ комментарий)
  → WARNING: снимается 1 предупреждение · MUTE/BAN: реальный unmute/unban в Telegram
  → пользователь получает решение в ЛС
```

## Как определяется, к какому наказанию относится апелляция

Кнопки в самом уведомлении нет намеренно: пользователь должен ответить (Reply) именно
на сообщение о наказании. Telegram передаёт id этого сообщения в `reply_to_message`,
а сам id при отправке уведомления сохраняется в `ModerationAction.metadata.appealDmMessageId`.
Это точнее, чем брать «последнее наказание пользователя» — работает даже если у
человека несколько активных наказаний в разных чатах одновременно.

## Отложенная доставка уведомления

Telegram не позволяет боту первым написать пользователю, который никогда не открывал
с ним диалог. Если попытка уведомить о наказании сразу после его выдачи не удалась,
Modera не сдаётся: как только этот пользователь сам напишет боту в личку что угодно
(например, `/start`), необработанные уведомления о наказаниях досылаются в этот момент
(`deliverPendingAppealNotifications`, до 3 наказаний за раз, только те, что ещё не
доставлены и по которым ещё нет апелляции). Само по себе это не решает задачу
«откуда пользователь узнает, что нужно написать боту» — это должен подсказать
администратор, например строкой в описании чата вида «Получили мут? Апелляция → ссылка
на бота».

**Ephemeral-уведомление (Bot API 10.2, добавлено позже).** Параллельно с попыткой ЛС
`notifyPunishmentAppealOption` теперь отправляет ephemeral-сообщение прямо в чат, где
выдано наказание — видимое только самому наказанному участнику, не требует, чтобы бот
уже был с ним в диалоге (работает, раз бот — администратор чата). Это не замена ЛС и не
новый канал подачи апелляции (сам `/appeal` по-прежнему подаётся Reply на сообщение из
ЛС) — просто более надёжный способ мгновенно сообщить о наказании и подсказать написать
боту, вместо того чтобы полагаться на то, что администратор когда-нибудь укажет ссылку
на бота в описании чата. Текст (отдельный на WARNING/MUTE/BAN, плейсхолдеры `%chat%`,
`%reason%`, `%contact%`) редактируется через панель — «Ручная модерация», хотя срабатывает
уведомление независимо от источника наказания, не только от ручных команд. Работает для
WARNING/MUTE (участник ещё в чате); для BAN
участник уже удалён из чата к этому моменту, поэтому попытка тихо не удаётся и остаётся
только ЛС/очередь.

## Честные ограничения этапа

- Пока пользователь ни разу не написал боту, у него физически нет способа подать
  апелляцию через ЛС-переписку — других каналов подачи в этой версии нет.
  Ephemeral-уведомление (выше) заметно снижает шанс, что пользователь вообще не узнает
  о наказании, но не даёт подать саму апелляцию в один тап. Каждая неудачная попытка
  ЛС-уведомления видна в журнале (`APPEAL_NOTIFICATION_FAILED`); неудачные попытки
  ephemeral-уведомления не логируются отдельно — это чисто вспомогательный канал.
- Одобрение апелляции на **бан** снимает блокировку в Telegram (`unbanChatMember`), но
  **не** возвращает пользователя в чат — Telegram принципиально не позволяет боту
  добавлять людей в группу без их собственного действия. Пользователю в ЛС отправляется
  только текст о том, что бан снят; ссылку на чат ему нужно получить отдельно.
- Если наказание уже было снято по другой причине к моменту рассмотрения (mute истёк,
  бан снят вручную), апелляция всё равно помечается одобренной без повторного
  обращения к Telegram — отменять уже нечего.
- Одна апелляция на одно наказание: повторный `/appeal` по уже поданному наказанию
  отклоняется ботом с соответствующим сообщением, а не создаёт дубликат.
- `/unmute` работает только для mute. Ban и warning всегда идут через `/appeal` и
  рассмотрение администратора — самостоятельно снять их нельзя, это намеренное решение.
- Счётчик самостоятельных разблокировок привязан к конкретному чату (`ChatMember`),
  а не к пользователю глобально — 3 попытки в одном чате не расходуют лимит в другом.
